4. 历史恢复保留累计预算，避免回滚状态后重置消耗。
5. 在正式总结之前执行自动测试、类型检查、生产构建和本地 API 主链路验证；具体结果见 TESTING。

## 模型结果的验证责任

结构检查：plan 只使用已启用的工具；report 的每条事实／推断有已存在 E 引用；异常证据不能作为正常事实；基础正则拦截直接交易建议和确定性收益。原始证据与引用可由人类核查。

当前不具备全自动语义证据蕴含验证。真实 OpenAI＋扶摇主链路已跑通；这不代表所有供应商功能已验证，也不能替代对研究结论的人工复核。

## 接入准备修正

查询官方文档确认：GPT-6.1 Sol 支持 API；更便宜的新模型 GPT-6 Luna 标准价输入 $0.10／输出 $0.50（每百万 Token）。扶摇 REST 需要 X-api-key，业务错误可能是 HTTP 200；资讯事件库不开放外部接入。代码改为明确标的和报告期、单位不换算、业务错误检查、全站原子预算预占。接入准备阶段尚未使用真实 Key，后续真实联调结果单独记录。

## 真实联调记录

用户授权复用本机 play-key 并保存到忽略的 .dev.vars，扶摇密钥同样仅保存在私密配置。线上通过服务端 Secret 管理。Codex 进行一次真实主链路联调并纠正边缘运行环境 redirect 参数兼容问题；2 次模型请求完成规划和报告。未声称 iFinD 已接入，正在等待其独立 MCP 配置。

Codex 逐项核验真实报告发现模型将 PCF 写为“现金流市值比”，与市现率（市值／经营现金流）的字段口径相反。加入限定语境下的术语规范和回归测试，不改原始数值，并在报告局限中提示复核。

线上三家公司验收发现网络较慢时自动步进会在第一个工具后停止：下一步定时器在当前 action 尚未结束时触发，busy guard 将其丢弃，状态不再变化。将 busy 纳入调度依赖，等待保存结束后再安排下一步；复用已有检查点继续验收，不重跑已完成的财务工具。

合规否定句回归：先验证“不保证收益／不提供买入建议”被错误拦截（测试失败），再区分明确免责声明与真正承诺／建议；“不建议买入”仍属于直接建议，继续拦截。修复后重试报告步骤，财务与估值证据不重复请求。

最终线上验证：三家公司财务和估值工具各调用一次；模型报告从失败检查点恢复后进入待复核，包含7条有引用的结论。累计模型请求6/15，保守预占约$0.0101/$1。未将真实金融原始值写入公开源码或测试记录。
